# LinguaStack — заметки для работы с кодом

Источник требований — `PROJECT` (ТЗ v1.1) и `docs/spec/SPEC-ADDENDUM.md`
(решения, которые ТЗ оставил открытыми; при расхождении с кодом прав ADD,
либо ADD обновляется вместе с кодом). План и отклонения от него —
`docs/superpowers/plans/2026-10-16-linguastack-core.md`.

## Окружение

* `export PATH=/root/go/bin:/usr/local/go/bin:$PATH` — `/usr/bin/go` здесь
  gccgo 1.16 и не годится. Тулчейн go1.27.2 задан в `backend/go.mod`.
* PostgreSQL: `docker compose up -d db` → `127.0.0.1:5434`. Порты 5432/5433
  и их контейнеры принадлежат другим проектам — не трогать.
* Ollama: `localhost:11434`, модель для живых тестов — `qwen3:8b`
  (на этой машине CPU, ~4 токена/с: живые тесты идут десятки секунд).

## Команды (из `backend/`)

```bash
make test        # все тесты без сети; нужна только БД
make lint        # golangci-lint v2 (.golangci.yml), должно быть 0 issues
make test-live   # с живым Ollama
go test -race -count=1 ./...
```

Живой тест Anthropic (`LINGUASTACK_LIVE_ANTHROPIC=1`) тратит деньги
пользователя — запускать только с его явного согласия.

Telegram: бот — отдельный процесс (`make run-bot`, без
`LINGUASTACK_TELEGRAM_BOT_TOKEN` выключен). Тесты бота и доставки идут
против поддельного Bot API `internal/telegram/telegramtest`, в Telegram
ничего не уходит.

Гейт коммита — цепочка через `&&` без `;`; если в ней есть `|`, то с
`set -o pipefail`: иначе код возврата даёт `grep`/`tail`, и коммит проходит
мимо упавших тестов.

PDF-фикстуры (`internal/importers/testdata/pdf/`) печатает headless Chrome:
`./generate.sh` в этом каталоге; результат коммитится, тестам Chrome не
нужен. Пул PDFium (wasm) общий на процесс и компилируется при первом PDF —
~3 с, под `-race` ~30 с.

## Веб-приложение (из `frontend/`)

```bash
npm run lint && npm run typecheck && npm test
npm run e2e      # нужен go в PATH (см. выше) и БД из docker compose
SCREENSHOTS=1 npm run e2e   # снимки в test-results/screens/ для визуальной вычитки
```

* Vue 3 + TypeScript, без UI-библиотек; цвета, шрифты и отступы — только
  токены из `src/styles/tokens.css`.
* Текст книги и перевода попадает в `v-html` только через `renderInline`
  (`src/lib/inline.ts` — сначала экранирует); правило `vue/no-v-html`
  включено, исключения — с комментарием-обоснованием.
* Версии npm-пакетов — точные и не моложе двух недель; `legacy-peer-deps`
  в `.npmrc` — обход сбоя npm 10 на peer-связи vitest (все peer перечислены
  явно).
* Интерфейс по-русски, кнопка называет действие; новые страницы — с
  проверкой на 390 px.

## Правила кода

* Комментарии, сообщения об ошибках и коммиты — по-русски, как в
  окружающем коде. Коммиты — conventional (`feat:`, `fix:`, `test:` …),
  автор — `git -c user.name="Kamil Vinokurov"`; коммитить только после
  зелёных тестов и линтера (`make lint && go test ./... && git commit`).
* TDD: сначала падающий тест, затем код; для исправлений — тест,
  воспроизводящий сбой.
* Схема БД — только версионные миграции goose (`backend/migrations`,
  встраиваются через `embed.go`). `AutoMigrate` не используется нигде,
  включая тесты. GORM — для моделей и запросов.
* Изоляция данных пользователей (ТЗ §2.1): доступ к чужому объекту — 404,
  а не 403; запросы к пользовательским объектам идут через `store.Owned*`.
  Новый маршрут регистрируется в `httpapi.Routes()` — матрица изоляции
  (`isolation_matrix_test.go`) проверяет все защищённые маршруты.
* Тесты с БД: `testdb.New` (транзакция с откатом) или `testdb.Committing`
  (отдельная БД пакета — для SKIP LOCKED и аренд). Фикстуры —
  `testdb.Make*`.
* Внешние модели в обычных тестах — только `providers.Fake`.
* Секреты не попадают в логи и тексты ошибок: логгер обёрнут
  `logging.NewRedactingHandler`, адаптеры вырезают ключ из ошибок.
* Инструменты записи файлов превращают escape-последовательности BOM
  (U+FEFF) и неразрывного пробела (U+00A0), набранные с обратной косой
  чертой, в буквальные невидимые символы. После записи Go-файла с ними
  проверить, что в исходнике остались именно escape-последовательности
  (буквальный BOM Go отвергает): `grep -nP '\x{FEFF}|\x{A0}' file.go`.
